# 深海秘宝转盘 H5｜项目归档 v1.0

归档日期：2026-08-29  
项目状态：本地可操作版本已完成并通过验收  
访问地址：<http://localhost:3000/spin>

## 1. 项目结论

本项目完成了一个移动端抽奖 H5，从最初的品牌营销转盘，迭代为“海底藏宝箱 × 捕鱼达人”风格的游戏化运营活动。

最终版本不是静态效果稿，而是包含抽奖状态、次数、概率、库存、幂等、记录、领取和刷新恢复的完整交互演示。

## 2. 最终产品定位

- 产品形态：移动端 H5 抽奖活动
- 核心主题：深海遗迹寻宝
- 视觉关键词：捕鱼、藏宝箱、黄金船舵、海底遗迹、金币、珊瑚、蓝金高光
- 目标体验：进入页面即可理解活动，转盘具备手游运营活动的刺激感和奖励反馈
- 演示边界：本地模拟，不连接真实账号、短信、物流和商业奖品后台

## 3. 已完成用户流程

1. 用户进入“深海秘宝”活动首页。
2. 查看剩余探宝券、活动倒计时和奖品转盘。
3. 点击“探宝 1 次”。
4. 系统生成唯一 `requestId`，先锁定抽奖结果并扣减库存。
5. 转盘根据已锁定结果播放动画并停在对应奖品。
6. 用户查看宝箱式开奖结果。
7. 中奖权益进入“秘宝库”，可通过模拟手机号验证领取。
8. 未中奖或次数不足时，可完成任务获得新的探宝券。
9. 抽奖记录、次数、任务、库存和领取状态在刷新后恢复。

## 4. 已完成功能

- 6 个奖项与固定概率

## 5. 最终字体规范

为保证常见移动 App 的可读性，最终采用以下保守字号体系：

- 页面默认正文：14px
- 常规辅助信息：13px
- 次要说明、时间与状态：最低 12px
- 主要按钮：14–16px
- 底部导航：12–13px
- 转盘奖品名称：12px
- 页面主标题：32–43px

转盘中央设置独立安全区，奖品图标和标签从安全区外开始径向排布，避免与中央按钮重叠。

## 12. 下一阶段建议

如果进入生产化阶段，推荐按以下顺序继续：

1. 将抽奖内核迁移到服务端，建立数据库事务与库存锁。
2. 接入用户身份、短信验证和活动资格校验。
3. 建立奖品、概率、库存、任务和活动时间配置后台。
4. 接入优惠券、积分、物流或第三方权益系统。
5. 增加反作弊、请求签名、频率限制和审计日志。
6. 补充真实设备兼容性、弱网、异常恢复和性能测试。
7. 完成正式部署、域名、埋点、监控和运营数据看板。

## 13. 本次工作流复盘

本项目验证出的有效流程为：

> PRD → 交互与规则建模 → 视觉方向校准 → 原创素材生成 → 页面组装 → 抽奖逻辑实现 → 移动端可读性修正 → 自动化验收 → 项目归档

关键经验：

- “完成 H5”必须指向最终用户产品，而不是工作流控制台。
- 抽奖页的价值不仅是转盘动画，还包括概率、库存、幂等和领奖闭环。
- 游戏化活动需要完整世界观和资产层，单纯更换配色无法形成手游感。
- 手机端正文不应为了信息密度压到 7–9px；保守字号体系更稳定。
- 转盘设计必须先定义中央安全区、奖品径向区域和外圈装饰区域。
